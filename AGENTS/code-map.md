# code-map — code map: what's where and how to read it

Anti-walk: do NOT read files in a row. Take a zone from here and make ONE targeted read of the
needed region (offset/limit).

### Flow diagram — `docs/workflow-arrows.puml` (+ generated `.svg`)

A one-screen map of how a request moves through the code: every code drawer (a folder of
same-concern modules — `scripts/lib`, `scripts`, `input/controllers`, …) and the numbered path
through a cross-cutting flow (`1..N`). Read it before changing a flow so you extend it in place
instead of adding a parallel path around it. Linted by `npm run workflow-arrows:lint`.
How to read / maintain / render → **AGENTS/workflow-arrows.md**.

### Hot zones (hand-maintained — verify against the code before use)

- build pipeline: `scripts/lib/build.mjs:buildProject` — content → datasets → engine → machine
  files; one build timestamp for every artifact.
- machine surface: `scripts/lib/machine.mjs:buildIndex` — index.json, well-known, feeds, tags,
  sitemap; generated, never hand-edited.
- copydeck: `scripts/lib/copy.mjs` — every human string; docs/SPEC.md §7 must agree verbatim.
- diagram drift: `scripts/workflow-arrows-lint.mjs:lintDiagram` — the puml must match the code tree.
- content gate: `scripts/validate.mjs:validateContent` — a BLOCK finding exits non-zero.
- module index: `scripts/contract.mjs:validateAll` — a header must equal a module's real
  exports/imports both ways.
