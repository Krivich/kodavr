## KDV-ARCH — Architectural decisions (§0)

- ✅ **KDV-ARCH-01**: Content, engine and CI live in a single static monorepo built by the Ignition SSG with no runtime backend. *(§0 A1–A2; flow: legacy)*
- 🟧 **KDV-ARCH-02**: Publication is a pull request and merge equals publication; discussions take place in GitHub Issues. *(§0 A3; PR template + CONTRIBUTING + deploy-on-merge tested — branch protection and Issues settings are manual; flow: legacy)*
- ✅ **KDV-ARCH-03**: The primary interface is machine-readable (`index.json`, per-dump manifests, feeds, sitemap); HTML is a projection for humans and SEO. *(§0 A4; flow: legacy)*
- ✅ **KDV-ARCH-04**: The human gate and the on-dump reception block are declarative only: the source is never blocked and the full body is present in the SSR HTML. *(§0 A6–A7; flow: legacy)*
- ✅ **KDV-ARCH-05**: A blanket 18+ rating applies to the entire site. *(§0 A8; flow: legacy)*
- ✅ **KDV-ARCH-06**: Engine/scripts code is MIT-licensed; dump content defaults to CC-BY-4.0. *(§0 A9; flow: legacy)*
- 🟧 **KDV-ARCH-07**: Production is hosted at `kodavr.xyz` on GitHub Pages; optional Cloudflare DNS uses grey cloud only. *(§0 A14; CNAME + runbook tested — live DNS/HTTPS unverifiable locally; flow: legacy)*

## KDV-STRUCT — Repository structure (§3)

- ✅ **KDV-STRUCT-01**: Every dump resides in `content/dumps/<slug>/`. *(§3; flow: legacy)*
- ✅ **KDV-STRUCT-02**: `manifest.json` is mandatory per dump and `raw.md` is the only mandatory body layer (`refined.md`/`summary.md` optional). *(§3, §A11; flow: legacy)*
- ✅ **KDV-STRUCT-03**: `type=pack` dumps contain `SETUP_AGENT.md`, `START_HERE.md`, `files/` and `checks/`. *(§3; flow: legacy)*
- ✅ **KDV-STRUCT-04**: `REDACTIONS.md` is present whenever sources include chat/correspondence. *(§3; flow: legacy)*
- ✅ **KDV-STRUCT-05**: `assets/` files are each < 1 MB; heavier/binary files live only in GitHub Releases. *(§3, §8.4; flow: legacy)*
- ✅ **KDV-STRUCT-06**: A slug matches `YYYY-MM-DD-<short-name>`, is unique, and equals both its directory name and `manifest.slug`. *(§3; flow: legacy)*
- 🟧 **KDV-STRUCT-07**: Author attribution (`author.github`, `author.pr_url`, `author.merged_at`) is extracted from the merged PR and never filled in manually. *(§3, §7.7; PR-payload extraction tested — live merged-PR metadata needs a remote; flow: legacy)*
- ✅ **KDV-STRUCT-08**: Root carries `README.md`, `LICENSE` (MIT), `LICENSE-CONTENT.md` (CC-BY-4.0), `CONTRIBUTING.md`, `docs/SPEC.md` and `docs/decisions.md`; `static/` is published as-is. *(§3; flow: legacy)*
- ✅ **KDV-STRUCT-09**: New dev scripts live in a two-level semantic subfolder `scripts/<category>/<process>/` grouped by category (`product`/`tooling`) and the business process they serve, never flat in `scripts/`; the shared publishing engine stays `scripts/lib/`, and a process folder may mix loose entry-point files with subfolders. The flat scripts are already regrouped. Enforced, not asked: `contract.mjs` walks `scripts/` recursively (every module needs a CONTRACT header) and the workflow map requires EVERY directory under `scripts/` to be a declared drawer. *(§3, §8.1; tests/unit/contract.test.js, tests/unit/workflow-arrows.test.js; flow: legacy)*

- ✅ **KDV-MOBILE-05**: Feed pagination uses 44px touch arrows (with optional swipe), the header is sticky with the logo while scrolling down, and a back-to-feed FAB sits bottom-right on dump pages. *(§6.5; declarative engine pagination — page 1 SSR at the root, separate page files kept reachable; swipe not implemented (optional); flow: legacy)*. The masthead is a CONTAINER-QUERY GRID keyed to its OWN content width (never the viewport): `container-type:inline-size;container-name:masthead` makes `.masthead` the query container, while the grid lives on the inner wrapper `.masthead-inner` (an element cannot be styled by its own container query), whose four direct children are, in DOM order, the mark, the species group, the nav and the switcher. Three deterministic states are driven by two `@container masthead (max-width:…)` blocks with literal thresholds (a container query cannot read a custom prop): NARROW (content < 520px) = row1 mark + switcher, row2 species chip FULL inner width, row3 nav FULL inner width; MID (520–860px) = row1 mark + chip + switcher, row2 nav FULL inner width; WIDE (> 860px) = one row mark · chip · nav (flushed right against the switcher by `justify-self:end` on the nav's own track, never `margin-left:auto`) · switcher. The switcher is pinned to `grid-row:1` in every state, so it can NEVER leave the mark's row at any width or locale; grid `align-items:center` centres its 44px tap box on the 34px mark, so the old relative `top:calc((var(--mark-size) - var(--tap)) / 2)` nudge is gone.
